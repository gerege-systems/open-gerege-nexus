# Муж ба гэр — нэршлийн засвар ба хувийн орон зайн санал

**Санал.** Урсгалуудыг дахин нэрлэнэ: `tenant` → **`workspace`**,
`internal/platform` → **`operator`**, `platform` schema → **`registry`**.
Мужид хоёр төрөл гарна — **гэр** (нэг хүн) ба **байгууллага**. Иргэн
байгууллагад харьяалагдалгүйгээр нэвтэрч, өөрийн мужид ажиллана.
`EID_JIT_TENANT_SLUG` устана. Нэг байсан access унтраалга хоёр болно:
платформ хүнийг оруулах уу, байгууллага гишүүн авах уу — тусдаа асуултууд.

Огноо: 2026-08-27 · Статус: **Үе A, B хэрэгжсэн (2026-08-27); Үе C–G санал** ·
Хамрах хүрээ: `backend/`, `frontend/`, `docs/`, `catalog/`

Шийдвэрийн товч нь [`adr/0006-a-person-owns-a-space.md`](adr/0006-a-person-owns-a-space.md).
Энэ баримт нь түүний **хэмжилт, хувилбар, дараалал**.

## 1. Юуг харсан бэ

Кодыг уншлаа. Доорх нь тоо ба байршилтайгаа.

### 1.1 `platform` гэдэг нэг үг дөрвөн зүйл хэлж байна

| Хэрэглээ | Утга | Тенантын урсгалын хамаарал |
| --- | --- | --- |
| `internal/platform/*` | Операторын урсгал | **Импорт хориотой** — `internal/planes_test.go` |
| `platform` schema | `users`, `tenants`, `apps`, quota, flags, announcements | **Заавал уншина** — нэрлэсэн 5 boundary хүснэгт |
| `pkg/platform` | Хоёр урсгалыг угсрах HTTP host package | Импортлодог |
| Прозод «платформ» | Бүтээгдэхүүн бүхэлдээ | `PlatformIsPublic()` нь `internal/tenant/auth`-д |

Эхний хоёр мөр эсрэг дүрэм үүрч байна: нэг `platform` руу хандаж болохгүй,
нөгөө `platform` руу заавал ханддаг. Архитектурын тодорхойлолт өөрөө үүнийг
тайлбарлахын тулд нэмэлт догол мөр бичих шаардлагатай болсон — *«бодит хил нь
schema USAGE биш, хүснэгтийн түвшний grant»*. Тэр өгүүлбэр хэрэгтэй болсон нь
нэршлийн зардал.

### 1.2 `tenant` бол адаптерын үг

ADR 0001: *«Домэйн бол хаана ажиллахаас үл хамааран үнэн зүйл. Адаптер бол
хаана ажиллаж байгааг мэддэг бүх зүйл.»*

`tenant` нь олон эзэмшигчтэй нэг суурилуулалт дээрх түрээслэгчийг заана —
энэ бол **байршлын** үг. Байгууллага харин хаана ажиллахаас үл хамааран
байгууллага.

Код өөрөө үнэн үгээ мэднэ. Нэг ч мөр өөрчлөхгүйгээр олдох жишээнүүд:

| Байршил | Бичигдсэн үг |
| --- | --- |
| `auth/tenants.go` | `ErrNoOrganisation`; *"Which organisation an account signs into when it does not say."* |
| `platform/tenants/tenants.go` | *"What the console may know about an organisation"*; `RegistrationNumber` |
| `db/migrations/00073` | `urtuu_reads_across_organisations` |
| `db/migrations/00076` | `the_org_chart_leaves_the_membership` |
| `frontend/app/organisation` | Байгууллагын legal profile |

**Тайлбар, миграцын нэр, ADR нь бүгд "organisation" руу нүүсэн. Зөвхөн
identifier нь `tenant` хэвээр үлдсэн.** Энэ бол нэршлийн санал биш, кодын
өөрийнх нь аль хэдийн гаргасан шийдвэрийг identifier-т буулгах ажил.

### 1.3 Хүн платформын түвшний баримт, гэвч гишүүнчлэлгүйгээр орж чадахгүй

`platform.users` глобал. `00082_users_ge_id` нь `ge_id`-д unique index тавьж
*«нэг geID = нэг хүн»* гэж бичсэн. Загвар нь хүнийг байгууллагаас
хамааралгүй гэж үзсэн байна.

Гэтэл `auth/tenants.go`:

```go
var ErrNoOrganisation = errors.New("this account does not belong to any organisation")
```

`FirstTenantFor` нь `tenant.memberships`-аас мөр олохгүй бол session нээгдэхгүй.
Схемийн зөвшөөрснийг нэвтрэлтийн код хориглож байгаа цорын ганц цэг энэ.

### 1.4 Одоогийн тойрч гарах зам нь env хувьсагч

`auth/handlers.go` дээр eID-ээр анх нэвтэрсэн иргэнийг `EID_JIT_TENANT_SLUG`
нэрлэсэн байгууллагад **гишүүн** болгож оруулна. Тэр иргэн:

- тухайн байгууллагын `CheckUserQuota`-д тоологдоно;
- түүний directory-д харагдана;
- түүний анхдагч role-ыг авна.

Кодын тайлбар өөрөө буруушаасан:

> *«provisioning somebody on their first eID sign-in is exactly the path by
> which an organisation grows without anybody choosing to add a person.»*

`accessmode.go` энэ асуултыг нэг газарт цуглуулж чадсан нь ахиц —
*«One check, at the one thing all of those paths do — create an account»* —
гэхдээ зөвхөн **бүртгэл үүсгэх эсэхийг**. Тэр бүртгэл **хаана амьдрахыг**
env хувьсагч шийдсэн хэвээр.

### 1.5 Нэг унтраалга хоёр асуулт хариулж байна

`settings.AccessMode` нь `private`/`public` хоёр утгатай. `public` гэдэг нь
өнөөдөр *«танихгүй хүн бүртгэл авна»* **ба** *(JIT slug тавьсан бол)*
*«тэр хүн миний байгууллагын гишүүн болно»* хоёуланг нэгэн зэрэг хэлж байна.

«Хаалттай систем дээр нээлттэй хэрэглэгч» гэдэг шаардлага яг энэ хоёрын
хооронд унаж байгаа юм.

## 2. Нэршлийн санал

### 2.1 Кодын нэр — олон улсын домэйний үг

| Одоо | Болох | Яагаад |
| --- | --- | --- |
| `internal/tenant`, `tenant` schema | `internal/workspace`, `workspace` schema | Hosting үгийг домэйний үгээр солино; гэр ба байгууллага хоёуланг барина |
| `internal/platform` | `internal/operator`, `operator` schema | `operator_accounts`, `operator_audit`, `gerege_nexus_operator` аль хэдийн байгаа — урсгал өөрийгөө нэрлэчихсэн |
| `platform` schema | `registry` schema | Суурилуулалтын бүртгэл: users, workspaces, apps, quota, flags |
| `pkg/platform` | `pkg/host` | Composition root, урсгал биш |
| Прозод «платформ» | «Gerege Nexus» / «суурилуулалт» | Бүтээгдэхүүний нэр урсгалын нэр байхаа болино |
| `internal/kernel` | өөрчлөгдөхгүй | Аль хэдийн зөв |

Үр дүнд `platform` дөрвөн утгаас **тэг** утга руу буурна, шинэ нэр бүр
нэг л зүйл заана.

### 2.2 Бүтээгдэхүүний толь бичиг — Монгол метафорын гэр бүл

`Гэрэгэ` ба `Өртөө` аль хэдийн нэг гэр бүл тавьсан. Түүнийг үргэлжлүүлнэ —
**гэхдээ UI, баримт, бүтээгдэхүүнд, Go пакетад биш**:

| Метафор | Юу | Байдал |
| --- | --- | --- |
| **Гэрэгэ** | Биедээ авч явах эрх — geID, нэвтрэлт | ✅ байгаа |
| **Өртөө** | Суурилуулалт хоорондын дамжлага | ✅ байгаа |
| **Гэр** | Нэг хүний өөрийн муж | 🆕 энэ санал |
| **Хот айл** | Хамтдаа буусан гэрүүд = байгууллага | 🆕 нэр, UI-д сонголтоор |
| **Тамга** | Зөвшөөрөл дардаг лац = операторын консол | 🆕 нэр |

**Метафорыг Go пакетын нэр болгохгүй.** `pkg/nexus` бол 7 хэлтэй, гадны
distribution хөгжүүлэгчид уншдаг semver гэрээ. Каир дахь module зохиогч
«хот айл» гэж юу болохыг мэдэх шаардлагагүй байх ёстой. `urtuu` энэ дүрмийг
зөрчсөн ч зөвтгөгддөг: `pkg/urtuu`-гийн тайлбар өөрөө шалтгааныг нь бичсэн —
англиар түүнийг нэрлэх үг байхгүй, «relay-post network» гэдэг тайлбар болохоос
нэр биш. «Байгууллага»-д тийм шалтаг байхгүй: `organisation`, `workspace`
хоёр долоон хэлэнд бүрэн орчуулагдана.

### 2.3 Татгалзсан нэршлийн хувилбарууд

| Хувилбар | Авах | Алдах |
| --- | --- | --- |
| Бүрэн метафор: `ger`, `khotail`, `tamga`, `nutag` | Хамгийн санахад амархан, экосистемтэй нэг өнгө | Гадны module зохиогчид хаалт; 7 хэлний орчуулгад найдваргүй; `Өргөө`/`Өртөө` нэг үсгээр ялгаатай — код болон ярианд эндүүрэл |
| `tenant` хэвээр, зөвхөн UI засах | Хамгийн хямд | `platform`-ийн дөрвөн утга үлдэнэ; хувийн муж орж ирэхэд `tenant` эцэслэн худал болно |
| `org` (`workspace`-ийн оронд) | Хамгийн богино, хамгийн үнэн — өнөөдрийн хувьд | Хувийн мужийг барихгүй: «personal org» бол өөрийгөө няцаасан нэр |
| `account` | SaaS-д танил | `platform.users`-тэй ойлголтын мөргөлдөөн |

`workspace` сонгосон шалтгаан: гэр ба байгууллага хоёуланг зөв багтаадаг
цорын ганц үг. Монголоор **«муж»** — «ажлын муж» гэдэг нэр томьёо
`SHELL_CONTRACT.md`-д аль хэдийн хэрэглэгдсэн байна.

## 3. Хувийн орон зай — гурван хувилбар

### 3.1 A — Гурав дахь plane

`internal/personal`, өөрийн origin, cookie, schema, DB role. ADR 0005-ийн
хэлбэрийг дагана.

**Татгалзсан.** `pkg/nexus`-ийн public contract-ийн **57 мөр** `tenantID`
дурддаг — `ReportEngine.Run`, `PermissionStore.GetUserPermissions`,
`Link.Enqueue`, `Directory.People`, `DocumentFiler.File`. Гурав дахь plane
гэдэг нь **тэнд ямар ч апп ажиллахгүй** гэсэн үг. Нэмээд ADR 0005-ийн гурван
үндэслэл (allowlist, олдоцгүй байдал, cookie тусгаарлалт) бүгд *операторын*
эрхээс үүдэлтэй; хувийн хэрэглэгч бол операторын эсрэг тал биш.

### 3.2 B — Хувийн муж нь муж мөр

Хүн бүрт `kind='personal'` мөр, ганц гишүүн нь өөрөө.

**Авах:** RLS, `dbguard`, module contract, app installation, permission gate —
бүгд **өөрчлөлтгүй** ажиллана. Хэрэгжүүлэлт нь нэг багана, нэг үүсгэх зам.

**Алдах:** мөрийн тоо (иргэн бүрээр), консолын жагсаалт (`tenantPageSize = 200`,
paging **байхгүй**), quota/metering-ийн утга.

### 3.3 C — Tenant-гүй session

Session нь хүн + **сонголтоор** муж. Route-ууд хүн-хамаарал ба муж-хамаарал
гэж хуваагдана.

**Авах:** хамгийн үнэн загвар — хүн бол субьект, муж бол контекст.

**Алдах:** `claims.TenantID` хоосон биш гэсэн таамгийг **бүх handler**-аас
ухаж гаргана; SDK-гийн `tenantID` хүн-хамаарлын route дээр худал болно.

### 3.4 Санал: **механизм нь B, толь бичиг нь C**

Хувийн орон зай дотооддоо муж мөр байна (B-ийн бүх ашиг), гэхдээ гадагшаа
хэзээ ч «байгууллага» гэж нэрлэгдэхгүй, байгууллагын дүрмийг үүрэхгүй (C-ийн
загвар). Тодруулбал:

**1. `kind` багана.** `registry.workspaces.kind ∈ {personal, organisation}`.
Консолын жагсаалт анхдагчаар `kind='organisation'` шүүнэ.

**2. Залхуу үүсгэлт.** Гэр нь **нэвтрэх үед биш**, хүн эхний удаа хадгалах
зүйлтэй болох үед үүснэ — гарын үсэг зурах, Өртөөгөөр даалгавар авах, апп
суулгах, баримт хүлээж авах. Эс тэгвээс eID товч дарсан бүх хүнээр хүснэгт
дүүрнэ. Идемпотент түлхүүр нь `ge_id`; түүнгүй бол бүртгэлийн `id`.
`00082`-ийн unique index энэ баталгааг аль хэдийн барьж байна.

**3. `EID_JIT_TENANT_SLUG` устана.** eID нэвтрэлт хүнийг үүсгэнэ, шаардвал
түүний гэрийг үүсгэнэ, өөр юу ч биш.

**4. Гэрт байхгүй зүйлс.** Урилга, role удирдлага, directory, хэлтсийн бүтэц,
байгууллагын квот. Гэрт нэг л дүрэм: эзэн нь бүх эрхтэй.

**5. Каталогийн `audience`.** Manifest-д `audience: personal | organisation | both`.
Үгүй бол хэлтэс, албан тушаал, батлах гинжин дээр босгосон апп хувийн мужид
утгагүйгээр урсаж орно. Анхдагч нь `organisation` — өнөөгийн бүх апп зөв
хэвээр үлдэнэ.

**6. Хоёр унтраалга.**

| Унтраалга | Асуулт | Анхдагч |
| --- | --- | --- |
| `registry.settings` → `access_mode` | Танихгүй хүн **өөрийн гэр** нээж болох уу? | `private` |
| `registry.workspaces.admission` | Хүн **энэ байгууллагад** орж болох уу? | `invite_only` |

Төрийн порталын хэлбэр яг энэ: eID-тэй хүн бүр орж **өөрийн зүйлээ** харна;
яамны ажлын мужид хэн ч урилгагүй ороогүй хэвээр.

**7. UX нь аль хэдийн бэлэн.** Мужийн сэлгүүр (`auth/session_switch_test.go`)
байгаа тул хэрэглэгчийн харах өөрчлөлт нь тэр жагсаалтад «Миний гэр» гэсэн
нэг мөр нэмэгдэх, тэгээд л боллоо.

## 4. Үе шатууд

Big-bang рефактор биш. Үе бүр дангаараа `main`-д орох чадвартай.

### Үе A — Үг тодруулах (кодын өөрчлөлт байхгүй) ✅ хэрэгжсэн

- `README.md`, `docs/*` дээр «платформ» гэдэг үгийг ялган нэрлэх:
  суурилуулалт / операторын урсгал / бүртгэлийн schema.
- `docs/TRANSLATION_GUIDE.md`-ийн толь бичигт **муж, гэр, байгууллага,
  оператор, бүртгэл** нэмэх — долоон хэлний орчуулга үүнээс эхэлнэ.
- ADR 0006 нэвтэрнэ.

**Эрсдэл:** тэг.

**Хэрэгжсэн байдал.** `TRANSLATION_GUIDE.md` §9 нь толь бичиг — долоон
хэлний орчуулга тэндээс эхэлнэ. Муж, гэр, бүртгэл гурав нь тусад нь
«захиалсан үгс» болж, Үе C хүртэл интерфэйст хэрэглэхгүй гэж тэмдэглэгдсэн:
муж бүр байгууллага байхад «ажлын муж» гэж солих нь зөвхөн бүрхэг болгоно.
Архитектурын тодорхойлолт, `CONTROL_PLANE.md`, `README.md`-д «платформын
урсгал» → «операторын урсгал» болов; бүтээгдэхүүнийг заасан «платформ»
хэвээр — интерфэйст тэр үг эхнээсээ ганц утгатай байсан.

### Үе B — `internal/platform` → `internal/operator`, `pkg/platform` → `pkg/host` ✅ хэрэгжсэн

Механик rename. Semver-т **нөлөөгүй** (`internal/`), эсвэл host package
(distribution-ууд import хийдэг — `pkg/platform` үлдээж, `pkg/host` руу
нэг мөрөөр delegate хийж, дараагийн major-т хасна).

**Баталгаа:** `pkg/platform/testdata/routes.txt` (213 мөр) **өөрчлөгдөөгүй**
байх ёстой. Өөрчлөгдвөл rename биш, зан төлөв өөрчилсөн байна.

**Эрсдэл:** бага. Ашиг: `platform` дөрвөн утгаас хоёр болж буурна, хилийг
хамгаалдаг `internal/planes_test.go` нэрээрээ уншигддаг болно.

**Хэрэгжсэн байдал.** Хоёр commit. `routes.txt` 213 мөр, sha `75e87303`
өөрчлөгдөөгүй — rename мөн, зан төлөв өөрчлөөгүй. `pkg/platform` нь
`Options` alias болон нэг мөрийн `Run` болж үлдсэн; `sso-`, `business-`,
`pos-gerege-nexus` гурвыг локал core руу `replace` хийж, `main.go`-г нь
огт өөрчлөхгүйгээр build хийж баталсан. Хасалт нь дараагийн major.

### Үе C — Хувийн муж (B+C загвар)

1. `kind` багана + миграц; байгаа бүх мөр `organisation`.
2. Консолын жагсаалтад **paging** — `tenantPageSize = 200` таг нь энэ үеийн
   **урьдчилсан нөхцөл**, дараа нь биш.
3. `admission` багана; `access_mode`-ийн утгыг хоёр болгож салгах.
4. Залхуу үүсгэлтийн зам + `ge_id` идемпотент.
5. `FirstTenantFor` → гишүүнчлэлгүй хүнд гэрийг нь буцаана;
   `ErrNoOrganisation` нь «энэ *байгууллагад*» гэсэн утгатай болж нарийсна.
6. `EID_JIT_TENANT_SLUG` устгах + `.env.example` шинэчлэх.
7. Metering: гэрийн bucket тусдаа.

**Баталгаа:** гишүүнчлэлгүй хүн нэвтэрч, зөвхөн өөрийн мужийг хардаг тест;
гэр байгууллагын консолын жагсаалтад **гарахгүй** тест; RLS-ийн тусгаарлалт
хоёр гэрийн хооронд ажилладаг тест.

### Үе D — Каталогийн `audience`

Manifest талбар, анхдагч `organisation`, app store шүүлт.

### Үе E — `tenant` → `workspace` дотоод rename

`internal/`, `frontend/`, шинэ код. SDK-д хүрэхгүй.

### Үе F — `pkg/nexus`: `tenantID` → `workspaceID`

**Зөвхөн дараагийн major.** `RELEASING.md`-ийн semver амлалтын дагуу.
`api.txt` snapshot байгаа нь азтай: рефакторыг механикаар шалгана — diff нь
яг 57 мөр байх ёстой.

### Үе G — Schema rename (эсвэл огт хийхгүй)

`ALTER SCHEMA platform RENAME TO registry`, `tenant RENAME TO workspace`,
grant/RLS/`search_path` нэг миграцад. 82 хуучин миграц хуучин нэрээрээ
replay хийгдэх тул шинэ DB босгоход эмх замбараагүй болохгүй.

**Энэ үеийг хийхгүй байх нь бүрэн зөвшөөрөгдөнө.** Schema нэр бол дотоод;
ашиг нь хамгийн бага, эрсдэл нь хамгийн өндөр. Үе A–F-гүйгээр G утгагүй;
G-гүйгээр A–F бүрэн утгатай.

## 5. Нээлттэй асуултууд

1. **Гэр Өртөөний peer байж чадах уу?** `00073_urtuu_reads_across_organisations`
   нь байгууллага хоорондын уншилтыг нээсэн. Иргэн даалгавар хүлээж авах нь
   энэ загварын хэдэн хувь вэ — тусдаа шийдвэр шаардана.
2. **Гэрээ устгах = муж устгах.** `deletion_scheduled_at` lifecycle байгаа нь
   сайн, гэхдээ иргэний өөрийнх нь хүсэлтээр устгах урсгал нь операторын
   устгах урсгалаас өөр (өөрийн шийдвэр, зөвшөөрөл, экспорт).
3. **Гэрээс байгууллага руу шилжих өгөгдөл.** Иргэн хувиараа гарын үсэг
   зурсан баримтаа дараа нь байгууллагадаа авчрах уу? Хариулт нь «үгүй» бол
   тэр өгүүлбэрийг хаа нэгтээ бичих ёстой.
4. **Гэрт квот хэрэгтэй юу?** Хэрэггүй гэвэл сая гэр нь storage-ийн
   төлөвлөгөөгүй өсөлт.
5. **Гэрийн тоо хэдээс хойш `registry.workspaces` хоёр хүснэгт болох вэ?**
   Хэмжилтийн шийдвэр; одоо хийхгүй, гэхдээ хэмжүүрийг нь одооноос авна.

## 6. Юуг санал болгоогүй вэ

- **Одоо байгаа хилийг сулруулахыг.** Хоёр урсгал, хоёр origin, хоёр
  identity — ADR 0005 хэвээр. Энэ санал зөвхөн тэдгээрийн **нэрийг** засна.
- **Гурав дахь plane.** §3.1-д яагаад болохгүйг бичсэн.
- **Бүх зүйлийг нэг дор нэрлэхийг.** Үе A–B хийгээд зогсох нь бүрэн хүчинтэй
  үр дүн: `platform`-ийн олон утга задарна, хувийн муж нь дараагийн шийдвэр
  хэвээр үлдэнэ.
